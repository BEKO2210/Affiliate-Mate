03 / EVALUATION

Learning without rewriting history.

Affiliate-Mate records what was known at forecast time, then evaluates only against outcomes that were actually observable by the evaluation time.

THREE-CLOCK MODELanti-leakage
effective_atWhen reality happened
→
observed_atWhen the source reported it
→
ingested_atWhen the system learned it

A conversion attributed to January but first reported in February cannot leak into a January evaluation.

OUT-OF-SAMPLE

Chronological holdouts

Candidate policies are evaluated after the training cutoff, not on the data used to derive them.

ROBUSTNESS

Walk-forward evaluation

Ordered folds reduce the chance that one lucky split creates a false promotion signal.

OBSERVABILITY

Counterfactual gate

A challenger cannot look superior by selecting historical cases for which outcomes were never observable.

AUTHORITY

No auto-promotion

Promotion eligibility is review evidence — never an invisible production-policy switch.

04 / DEVELOPER EXPERIENCE

Built to be operated, tested, and recovered.

A single product CLI sits over explicit domain boundaries, portable workspaces, stable exit codes, and compatibility shims.

quickstart
# install from source
git clone https://github.com/BEKO2210/Affiliate-Mate.git
cd Affiliate-Mate
python -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[dev]"

# run without credentials
affiliate-mate demo init ./demo
cd demo
affiliate-mate status
affiliate-mate doctor

# verify the stable product contract
affiliate-mate-release verify
