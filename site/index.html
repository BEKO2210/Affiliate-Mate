03 / EVALUATION

Learning without rewriting history.

Affiliate-Mate records what was known when a forecast was made, then evaluates against outcomes only when they were actually observable.

THREE-CLOCK MODELanti-leakage
effective_atWhen reality happened
→
observed_atWhen source reported it
→
ingested_atWhen the system learned it

A January conversion first reported in February cannot leak into a January backtest. Historical evaluation sees only information actually available at evaluation time.

OUT-OF-SAMPLE

Chronological holdouts

Candidate policies are evaluated after the training cutoff, never on the data used to derive them.

ROBUSTNESS

Walk-forward evaluation

Multiple ordered folds reduce the chance that one lucky split creates a false promotion signal.

CALIBRATION

Confidence-aware metrics

CTR and conversion calibration expose Wilson intervals and minimum-sample safeguards instead of false precision.

AUTHORITY

No auto-promotion

“Promotion eligible” is evidence for review — not an invisible switch that changes production behavior.

04 / DEVELOPER EXPERIENCE

Built to be operated, not babysat.

A single product-facing CLI sits on top of explicit domain boundaries, with deterministic local paths and compatibility shims for existing automation.

quickstart
# install from source
git clone https://github.com/BEKO2210/Affiliate-Mate.git
cd Affiliate-Mate
python -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[dev]"

# create a credential-free workspace
affiliate-mate demo init ./demo
cd demo
affiliate-mate status
